#**UX Notes - Pros and Cons of the frontend**

#**Desktop view**

##**Pros:**

1. Color gradients are perfect.
2. Spacing are accurate between elements.
3. Buttons are responsive.
4. Simple to walkthrough the page.
5. Comprehensive information listings.
6. High Modularity.

##**Confusing elements:**

1. **"Band native coordination, remote triage agent validation, static showcase"** - looks like buttons(but they aren't)
2. **"Validated Proof"** is unnecessary - suggested to remove.
3. Under **"Demo Flow"**: the 'Example Incident' and 'Flow' -- hierarchical misarrangement and difficult to interpret.
4. Under **"Architecture"**: 'Static endpoint reference' increases confusion -- suggesting to remove them.
5. Repetition of **"Native.builder/nativeai"** card -- increases ambiguity (strongly suggesting for removal)

##**Improvements:**

1. Wordmark(next to Logo) font change.
2. Each section headers can be big, bold and visible.
3. Certain sections(Problem, solution) can include some styling.
4. **Live Demo: Coming Soon"** button can be centred among **"GitHub repo"** and **"Demo video"** buttons.
5. **Back to Top** icon must be included.
6. Margin alignment for the whole page is recommended(Extra gap between the edge of the screen and content).

##**Label Change:**

1. **Agent Team** -> **Agent Workforce** (More technical)
2. Under **Agent Workforce:"
	2.1. **Validated remote proof(Triage agent)** -> **Incident Validation**
	2.2. **Expansion Path(Threat Intel agent)**   -> **Threat Attribution**
	2.3. **Expansion Path(Forensics Agent)**      -> **Evidence Timeline**
	2.4. **Expansion Path(Compliance Agent)**     -> **Governance Review**
	2.5. **Expansion Path(Incident Commander)**   -> **Containment Decision**
3. Under **Architecture**:
	~Add **System Architecture Layers** or **Band-centric coordination Architecture** label on top of the layers classification.
